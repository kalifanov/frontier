# FRONTIER

Мобильный HTML-концепт тактического автобаттлера по мотивам структуры Rush: один командир, три бойца, автоматический бой за башню и продвижение к базе противника.

**Текущая версия — игра против локального ИИ. Сетевого PvP нет.**

## Запуск

Самый простой способ: скачать **`frontier.html`** и открыть в браузере. Это готовый автономный HTML-файл; сервер и установка не нужны.

Для работы с исходниками:

Нужен Node.js 20 или новее. Устанавливать зависимости не требуется.

```sh
npm start
```

Открыть [http://127.0.0.1:4173](http://127.0.0.1:4173). Альтернатива: `node server.mjs`.

Файлы `index.html`, `styles.css`, `app.js` и `game.js` можно разместить на любом статическом HTTP-хостинге. Исходный `index.html` требует HTTP для ES-модулей; автономный `frontier.html` работает и через `file://`. Google Fonts используются для типографики; при отсутствии сети работают системные шрифты. Карта, персонажи и иконки создаются кодом, внешние изображения не загружаются.

После изменений выполнить `npm run build`, чтобы обновить автономный HTML.

## Игровой цикл

1. Выбрать бойца в нижней панели.
2. На телефоне открыть «Изменить», на широком экране — настроить приказы справа: маршрут, задача, задержка выхода 0–4 секунды.
3. В арсенале купить оружие, броню и дымовую. У каждого бойца отдельный кошелёк.
4. Нажать «Начать бой». После старта команды не меняются.
5. Изучить результат, пополнить снаряжение и перейти к следующему раунду.

## Что работает

- Мобильная вёрстка, отдельные нижние панели приказов и арсенала, широкая компоновка для компьютера.
- Три бойца против трёх; ИИ выбирает приказы и покупает экипировку.
- Четыре геометрии арен и цепочка из семи секторов; первый бой в центре.
- A* для обхода укрытий; блокировка обзора стенами и дымом.
- Пять видов оружия, разная дальность, точность, скорострельность, урон, магазины и перезарядка.
- Автоматический захват башни, таймер, семисекундное окно после уничтожения защитников.
- 40 секунд на обычной арене; 60 на базах и решающей арене.
- Победа сдвигает следующий бой к базе врага. Матч заканчивается победой на чужой базе или восьмой победой; при 7:7 активируется решающая арена.
- Отдельные бюджеты: $800 на старте, $10 000 максимум. Победителю $2 500, проигравшему $2 100 с ростом серии поражений на $750 до $5 100; по $200 за устранение.
- Оружие и броня выживших сохраняются, у погибших сбрасываются; использованный дым расходуется. Новые покупки можно отменять до боя.
- Недоступные покупки блокируются. Возврат сохранённой экипировки не создаёт деньги.
- При скрытой вкладке симуляция приостанавливается.

## Границы концепта

Подготовка без таймера, захват занимает 0,35 секунды, параметры оружия и экономика упрощены для демонстрации. Базы используют геометрию обычных арен; решающий сектор имеет отдельное название и таймер, но не отдельную геометрию. Повторение типов арен допустимо. Нет серверной симуляции, матчмейкинга, аккаунтов и сохранения прогресса. Настоящий PvP потребует авторитетного сервера и синхронизации скрытых приказов.

Исходная идея режима: [Valve — Rush Hour](https://www.counter-strike.net/newsentry/711161056325533826). Справочник численных правил: [Source2 Wiki — Rush](https://www.source2.wiki/Scripting/Counter-Strike%202/rush), неофициальный источник. Frontier — самостоятельный концепт; ассеты Valve не используются.

## Проверки

```sh
npm test
```

Тесты проверяют проходимость всех карт, отсутствие движения через стены, завершение и детерминированность боя, правила захвата после уничтожения защитников, блокировку обзора дымом и экономику закупки.

## Структура

| Файл | Назначение |
| --- | --- |
| `index.html` | Экран матча и диалоговые панели |
| `styles.css` | Адаптивная вёрстка и визуальная система |
| `app.js` | Интерфейс, Canvas-рендер, цикл матча и ИИ закупки |
| `game.js` | Боевая симуляция, карты, A*, оружие и закупка |
| `server.mjs` | Локальная раздача только публичных файлов концепта |
| `build.mjs` | Сборка автономного HTML без зависимостей |
| `frontier.html` | Готовый концепт для открытия и передачи одним файлом |
| `tests/game.test.js` | Проверки ключевых правил |

SSH-ключи не входят в проект. Локальный deploy key и `known_hosts` хранятся вне репозитория; путь к ключу задан только в локальной Git-конфигурации.
